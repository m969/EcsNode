# 玩家资源模块程序单元测试设计文档

## 1. 模块程序单元测试概述

- **测试目标**  
  验证玩家资源模块的各项功能实现的正确性、稳定性和健壮性，包括资源的获取、消耗、同步、变更、统计、日志记录、批量操作、合法性校验及异常处理等。

- **测试范围**  
  涵盖资源数据组件、资源变更记录实体及其对应系统的所有核心接口和逻辑流程。

备注（1.0.1）：移除对资源变更组件（ResourceChangeComponent）及资源变更系统（ResourceChangeSystem）的测试范围描述；单次资源变更相关测试聚合到资源数据系统（ResourceDataSystem）的接口用例中。

备注（1.0.2）：新增节点派发接口测试范围：`IResourceChanged`, `IResourceSynced`。需验证资源增减/批量变更/同步/持久化场景下事件正确派发次数与参数。

| TC13     | 事件与失败操作隔离测试 | 验证失败不派发                 | 1. 构造非法消耗<br>2. 校验无回调         | 无 IResourceChanged 事件       |

## 3. 模块程序单元测试执行

- **测试环境准备**  
  - Unity编辑器及EcsNode框架环境
  - 配置测试用例所需的实体和组件

- **测试数据准备**  
  - 初始化玩家资源数据
  - 构造各类资源变更参数及边界数据
  - 构建事件监听桩（Mock/Spy）记录派发次数与参数

- **测试执行步骤**  
  1. 按测试用例逐项执行接口调用
  2. 记录每步操作结果及系统状态
  3. 对比实际结果与预期结果
  4. 对事件相关用例，断言派发接口捕获到的参数（资源类型、delta、newValue、changeType、reason / syncTime）
